# Telegram версия запущена — 24.11.2026

На `fornex.pravburo`, `/opt/pravburo-chatwoot` запущен отдельный Compose project `pravburo-chatwoot`. Все постоянные сервисы работают, сервисы с healthcheck здоровы, оба migration job завершились с кодом 0. Внутренний HTTP — `127.0.0.1:8088`, публичный HTTPS — `https://mess.prav-buro.ru`. Состав контейнеров остальных приложений не изменён.

Основной адрес: [войти в приложение](https://mess.prav-buro.ru/app/login). Менеджерам SSH не нужен. Первоначальные логины и пароли сохранены только в локальном `secrets/server-access.txt` (0600) и серверном `.env` (0600), в отчёт не включены. Инструкция: [подключить Telegram и добавить менеджеров](user-guide.md).

Технический администратор подключает Telegram через API ID/Hash, код и 2FA. Руководитель создаёт/отключает менеджеров, распределяет клиентов и видит журнал назначений. Менеджеры видят своих клиентов. Telegram ещё не авторизован; проверка настоящего обмена требует входа владельца и пилота на тестовых собеседниках. MAX отложен, Enterprise отсутствует.

## Фактические проверки

- 20 Rails specs, 7 Django, 6 gateway tests прошли. Код/2FA, voice/reply и исключение служебных кодов Telegram проверены на подменённом клиенте.
- Финальные локальные HTTP/WebSocket/file и браузерные проверки изоляции, создание/отключение менеджера, фильтр и передача клиента прошли. Сквозной mock обмен, документ, правки/удаления и отсутствие дублей прошли.
- Серверный browser smoke подтвердил оба входа, форму подключения Telegram и управление менеджерами. Клиентских тестовых фикстур на сервере нет. Один запрещённый запрос счётчика уведомлений технической роли возвращает 404, ошибок JavaScript нет.
- Runtime подтвердил CE SHA, отсутствие Enterprise/его расширений, миграции, роль БД без superuser, Redis, Sidekiq heartbeat и local storage.
- Реальный серверный ClamAV пропустил чистый probe и заблокировал безопасный тест EICAR.
- Резервная копия обеих БД, файлов, Redis, `.env` и каталога Telegram создана в приватном `backups/`. Обе БД восстановлены в отдельные временные базы; файловые архивы читаются. Рабочая БД при проверке не перезаписывалась. Автоматическое расписание backup пока не включено.

Артефакты: [запуск](evidence/server-running.json), [runtime](evidence/server-runtime.json), [браузер](evidence/server-browser.json), [восстановление](evidence/server-backup.json), [ClamAV](evidence/server-antivirus.json), [чистая установка](evidence/fresh-install.json).

При первой установке исправлен порядок upstream prepare-task: load schema → migrate → seed. Патч отдельно проверен на пустой БД, затем применён небольшим слоем поверх CE образа. Исходники на сервере проверяются как `SOURCE-MANIFEST.json` плюс `SOURCE-UPDATES.json`; исходные архивы, образы и runtime patch сохранены в `releases/20261124/`.

Открыто до производственного приёма: живой Telegram пилот, нагрузочная проверка с нужным числом менеджеров, расписание/внешнее хранение резервных копий и устранение оставшихся lint предупреждений/замечаний сложности. Старая история Telegram целиком не импортируется. Неизвестный исход отправки не повторяется автоматически.

## HTTPS

Фактически созданная DNS запись — `mess.prav-buro.ru`, с дефисом. Для неё выпущен отдельный сертификат Let’s Encrypt и nginx vhost; остальные сайты не изменены. HTTP перенаправляется на HTTPS. Проверены оба входа, WSS, Secure/HttpOnly/SameSite=Strict media cookies и закрытость internal API. Автопродление обслуживается существующим `certbot.timer`; конфигурация сертификата содержит webroot и deploy hook для reload nginx.
