# Управление менеджерами

Страница `/app/accounts/:accountId/corporate/managers` открывается пунктом «Менеджеры» в боковой навигации или верхней панели. Доступ имеет только активный руководитель (`supervisor`). Техническая роль управления каналами и обычные менеджеры список не получают, в том числе через прямой URL/API.

## Возможности

- Все локальные менеджеры, включая отключённых; поиск по имени/почте, фильтр доступа, серверная пагинация по 25 строк.
- Общие показатели: сколько менеджеров создано, активно, отключено и связано с Bitrix24. По строкам — личные клиенты и их диалоги, отсутствие с открытием чатов, CRM ID, последний вход, количество активных браузерных подписок и подтверждённых тестов уведомлений. Чужие общие чаты не добавляются в личную нагрузку.
- Создание вручную или из действующего сотрудника Bitrix24. При импорте имя и почту сервер берёт из CRM; локальный менеджер и его привязка создаются одной транзакцией. Уже занятые CRM ID недоступны для повторного импорта. Изменение привязки с действующими связанными клиентами сохраняет прежнюю защиту.
- Редактирование имени, логина, пароля и привязки в одной форме. Смена логина/пароля отзывает прежние браузерные сессии, API-токен, media cookie и realtime-stream. Пустой пароль в форме не изменяет существующий пароль.
- Пароль нового сотрудника показывается только из памяти формы после успешного создания; повторное чтение пароля сервером отсутствует. Есть генерация и копирование. Закрытие очищает пароль; email-приглашения не отправляются.
- Отключение сразу отзывает доступ и запускает штатную передачу клиентов. Повторное отключение идемпотентно. Восстановление возможно после завершения очистки владельцев; старые сессии не восстанавливаются. Само восстановление не назначает клиентов; последующая штатная CRM-синхронизация действует по текущему ответственному Bitrix24.

Старая форма сотрудников и отдельный список CRM-сопоставлений убраны из выпадающей панели клиентов. Распределение клиентов и журнал назначений в ней остаются. Модель доступа к перепискам не расширяется.

## API v1

Все запросы требуют аутентификации текущего Chatwoot и роли руководителя в указанной организации. Новый каталог возвращает `api_version: 1`, `account_id`, `payload` и `meta` (`page`, `per_page`, отфильтрованный `total`, общая `summary`). Клиентские имена, тексты переписок, push endpoint, токены и секреты в каталоге отсутствуют.

| Метод и путь относительно `/api/v1/accounts/:accountId/corporate` | Назначение |
| --- | --- |
| GET `staff/directory?q=&status=all&page=1` | Новый полный каталог; `status` — `all`, `active`, `disabled`, поиск до 100 символов |
| GET `staff` | Совместимый прежний массив, ограниченный 200 строками; для новых интеграций использовать каталог |
| POST `staff` | Создание: `name`, `email`, `password`; с `bitrix_user_id` имя/почта берутся из CRM |
| PATCH `staff/:id` | Изменение `name`, `email`, `password`, `bitrix_user_id`; профиль и новая привязка атомарны |
| DELETE `staff/:id` | Отключение, а не физическое удаление сотрудника |
| POST `staff/:id/enable` | Восстановление; `409 cleanup_pending`, если передача клиентов не завершена |
| GET `crm/employees` | Действующие сотрудники CRM и занятые `assigned_ids`; прежние поля ответа сохранены |
| PUT `crm/employees/:id` | Совместимый прежний способ сопоставления |

Существующая сигнатура `Corporate::StaffService#create(attributes)` и прежний JSON `GET staff` сохранены. Новые роли/права не принимаются через изменение профиля. Внешняя сеть CRM не вызывается при чтении каталога; профиль можно открыть при сбое CRM. Внешний вызов проверки сотрудника выполняется до account lock.

## Производительность и безопасность

На страницу загружаются не более 25 пользователей, ассоциации предзагружаются. Владение и диалоги считаются сгруппированными запросами только для ID страницы; CRM-привязки — одним запросом; подписки ограничены account и пользователями страницы. Запросы написаны через ActiveRecord/Arel. Нагрузочный тест большого штата не выполнялся.

Задача очистки отключённого сотрудника повторно проверяет статус и текущего владельца под account lock для каждого клиента. Старая задача не снимает клиента с нового владельца и не продолжает очистку восстановленного сотрудника. Отправки с неизвестным результатом сохраняют существующее блокирование передачи; обхода проверки нет.

Изменений схемы БД, зависимостей, шлюзов и Enterprise-компонентов нет. Выпуск: `staff-admin-product-20261127`; предыдущий — `notifications-diagnostics-product-20261127`.

Проверки: 119 корпоративных Rails-сценариев; отдельные Vue-тесты каталога, смены account, импорта CRM и пустого пароля. Производственная браузерная приёмка не создаёт пользователей и не меняет существующие логины, пароли, доступы или привязки.

Производственная приёмка пройдена: три существующих менеджера и их CRM ID сохранены, поиск Валерия находит ID 482, генерация нового пароля и закрытие формы работают без сохранения, существующий пароль пуст, обычному менеджеру отказано в UI/API. Тестовые сессии отозваны. На текущих данных планы подсчёта личных клиентов/диалогов выполнены за 0,103/0,343 мс; это разовая проверка малого текущего объёма, не результат нагрузочного теста. Откат образа не восстанавливает изменённые пользователем пароли и доступы.
