# MAX Personal — рабочий выпуск 25.11.2026

Выпуск `max-product-20261125`: собственный пользовательский MAX шлюз подключён к Chatwoot Community Edition и общему контуру Bitrix24. Закрытые Enterprise-компоненты не используются. MAX_DELIVERY_ENABLED и MAX_CRM_ENABLED включены; ограничение одним тестовым собеседником снято после приёмки.

На выбранном владельцем тестовом собеседнике проверены QR/2FA, восстановление session после рестарта, первый текст по телефону, ответы, текст/фото/документы/голосовые в обе стороны, пересланные вложения и правка текста того же сообщения. Apple Numbers прошёл проверку реального типа, антивирус и повторную доставку после расширения списка разрешённых офисных типов. Старый архив до активации не импортировался. Внешняя платформа не даёт гарантии 100% доступности.

Браузерная приёмка: 24 проверки ролей и интерфейса; отдельно четыре проверки отправки двух выбранных файлов через Enter. Обе доставки подтверждены MAX, каждая содержит один файл и внешний ID, дублей внешних сообщений в тестовой беседе нет. Входящие фото, документ и голосовое отображаются с готовыми вложениями без ошибок. Неизвестные результаты ранних синтетических испытаний не отправлялись повторно; управляемая отмена теста не трактуется как подтверждение внешней доставки.

Отдельный MAX API inbox, явный channel в outbox и event keys, маршрутизация файлов/ACK/результатов по каналу. Падение MAX не блокирует Telegram. Приём сохраняет текст до загрузки медиа; файлы повторно загружаются при временной ошибке. Уведомление о собственном исходящем, пришедшее до ответа отправки, ожидает сверки и не создаёт дубликат. Неопределённый send сверяется чтением по устойчивому CID и не повторяется вслепую.

Один подтверждённый телефон объединяет идентичности мессенджеров с общей собственностью и CRM-записью. Ручная привязка анонимного MAX чата к уже связанной сделке переносит его к доступному актору клиенту; чужой клиент остаётся закрытым. Незавершённые отправки препятствуют переносу. Исходная карточка и аудит сохраняются, общий доступ отзывается. Предыдущий результат «сделка не найдена» не запрещает новый автоматический поиск.

При активации ссылка существующей CRM-записи тестового клиента обновляется без смены ответственного; тестовые сделки не создаются. В карточке CRM поле «Мессенджер» ведёт к активной беседе с проверкой прав владельца и руководителя; в чате доступна прежняя ссылка на лид/сделку. Проверки CRM использовали синтетические ответы и существующую конфигурацию: фиктивные лиды/сделки для испытаний не создавались. Telegram продолжает работать прежним шлюзом.

Код проверен 66 корпоративными Rails specs, 39 Django tests и 35 MAX tests, включая настоящие сигнатуры Dispatcher, Profile и истории закреплённого SDK. JS lint — без ошибок, одно предупреждение динамического i18n ключа. Ruby lint — без оставшихся замечаний.
