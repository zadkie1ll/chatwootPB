# Поиск переписки через контакт CRM — 25.11.2026

Код опубликован в https://github.com/zadkie1ll/chatwootPB, ветка main. Включён полный CE-код с корпоративными изменениями и исходной лицензией. Enterprise, секреты, Telegram session и эксплуатационные evidence исключены из GitHub. Скрипт scripts/export-github.py создаёт отдельную копию обычных файлов, без вложенного Git checkout.

Выпуск integration `contacts-20261125` добавляет поиск лида через контакты и компанию из поля «Клиент». Телефон может отсутствовать непосредственно в лиде. После поиска контактов/компаний по телефону выбирается последняя открытая сделка; при её отсутствии — последний открытый лид, найденный как по собственному телефону, так и по связанному клиенту. Прямые совпадения и совпадения через контакты сортируются совместно в CRM. Весь список CRM не выгружается, дополнительных запросов на каждого клиента нет.

Для проверенного существующего чата контакт по телефону найден, но его единственная сделка закрыта. Поэтому прежний фильтр открытых сделок закономерно возвращал «не найдено». Доступ webhook проверен: оба существующих профиля возвращают одинаковую картину. Статус и ответственный закрытой сделки при диагностике не менялись. Автоматическая привязка к закрытой сделке ожидает выбора владельца; текущая политика выбирает открытые объекты. Ручная привязка явной ссылкой доступна.

Проверки: 32 Django tests проходят. Через отдельный тестовый HTTPS-сервер с проверкой сертификата подтверждены последняя открытая сделка, лид по собственному телефону и лид, у которого телефон находится только в связанном контакте. Более новый закрытый лид исключён. Новые миграции БД не требовались; Telegram gateway при выпуске не перезапускался. Серверная приёмка зафиксирована в приватном evidence и release log.

Официальные контракты: [crm.item.list](https://apidocs.bitrix24.ru/api-reference/crm/universal/crm-item-list.html), [поля объектов, contactIds и stageSemanticId](https://apidocs.bitrix24.ru/api-reference/crm/universal/object-fields.html). Чтение CRM не раскрывает телефоны в отчётах, тестовые сообщения клиентам и фиктивные сделки не создавались.

Дополнительно на рабочем портале три проверки поиска по телефонам контактов открытых сделок дали 3 успешных результата. Это были только чтения; номера и карточки клиентов не экспортировались. В проверенной выборке открытых лидов с контактами не было, поэтому положительный сценарий лида подтверждён тестовым HTTPS-сервером.
