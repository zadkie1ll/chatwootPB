# Поиск собеседника и проверка номера

В новом диалоге (кнопка «+»), панели «Мои клиенты» и привязке к Битрикс24 вставленный российский номер приводится к `+7 (999) 123-45-67`. Начальная `8` заменяется на `+7`, десять цифр получают код страны. На сервер передаётся `+79991234567`. Неполные, слишком длинные и иностранные номера отклоняются без усечения.

Для Telegram доступны `@username`, простой username и ссылка `https://t.me/username`. Поиск принимает только личного собеседника или бота, не канал/группу. Если Telegram скрывает телефон, существующий проверенный номер клиента сохраняется; выдуманный номер в CRM не передаётся.

MAX принимает телефон. Для уже известных диалогов используется подтверждённое соответствие номера собеседнику, затем обычный поиск MAX. Наличие номера не гарантирует поиск незнакомого пользователя: учитываются ограничения MAX. Ошибка объясняет необходимость первого входящего сообщения, если поиск недоступен.

Резервный вход: https://mess.prav-buro.ru:18443/app/login. Использует тот же сертификат, авторизацию и права. Основной адрес сохраняется. HTTPS-порт разрешён владельцем; временное диагностическое правило TCPMSS удалено как неэффективное. Владелец подтвердил открытие страницы в Chrome и Safari. Авторизация и WebSocket проверяются отдельным браузерным сценарием.

Регрессионные проверки: Rails (нормализация и сохранение проверенного телефона), Telegram username, MAX поиск известного диалога, валидация integration resolve и frontend phone. Сценарий `tests/e2e/phone-input-production.mjs` перехватывает создание диалога, не отправляет сообщения и не ищет примерный номер в MAX.
