# Сервер: запуск разрешён после увеличения памяти

Первоначально владелец запретил запуск до увеличения памяти. 24.11.2026 тариф увеличен, владелец разрешил продолжить работу и довести Telegram до пользовательского сценария. Проверка: 7941 MiB общей, 5288 MiB доступной RAM; свободно около 98 GiB диска. MAX отложен; используется только Chatwoot Community Edition и собственный код.

Каталог: `/opt/pravburo-chatwoot`. Отдельное имя Compose: `pravburo-chatwoot`. Будущий HTTP listener: `127.0.0.1:8088`. Базы, Redis, gateway и внутренние API не публикуют порты. Существующие приложения и reverse proxy сервера не перенастраиваются.

## Что входит в подготовку

- Исходники модифицированного CE, Django integration, Telegram MTProto gateway, Dockerfile и Compose.
- Закреплённые digest базовых образов; ClamAV предназначен для amd64 сервера, включается профилем `antivirus`.
- Индивидуальные серверные секреты в `.env` (0600), приватные каталоги (0700). Локальные тестовые пароли, базы и Telegram sessions не переносятся.
- `SERVER_PREPARED_ONLY=true`: обёртка Compose запрещает создание, сборку и запуск контейнеров. Это защита от случайного запуска через обёртку, а не ограничение root-доступа.
- Проверка конфигурации и памяти без запуска приложения. Архив содержит `SOURCE-MANIFEST.json` с SHA256 каждого включённого файла.

## Что пока не сделано

Собраны образы Linux/amd64 для CE, integration и Telegram gateway. Перед запуском они переносятся с проверкой SHA256. Авторизованной Telegram session пока нет: владелец подключает её в интерфейсе. Фактический результат развёртывания записывается в docs/evidence/server-running.json.

Актуальный код прошёл 20 Rails specs и Python проверки. Сквозной синтетический Telegram проверил отправку, входящие, дедупликацию, правки, удаления, отсутствие эха, заметки и документ. Подключение кодом/2FA проверено с подменённым клиентом. Живой аккаунт и сообщения настоящим адресатам не проверены. Перед началом работы требуется пользовательский пилот.

Канал использует собственный durable outbox и polling. Generic API-inbox webhook оставлен выключенным: upstream SafeFetch закрывает приватную сеть, а ошибка webhook не должна помечать подтверждённую Telegram отправку как неудачную. HMAC endpoint integration поддерживается и тестируется, но не является источником доставки.

## После увеличения RAM

Предварительная диагностика сервера: около 4 GiB общей памяти, менее 0.2 GiB доступно, swap отсутствует; на сервере уже работают другие приложения. Стартовый барьер требует не менее 7600 MiB общей и 4096 MiB доступной памяти. Это минимальная проверка, не результат нагрузочного теста. С учётом существующих приложений целесообразно выделить серверу 12 GiB или больше и затем повторить диагностику.

1. Выполнить `ssh fornex.pravburo`, перейти в `/opt/pravburo-chatwoot`, запустить `python3 scripts/server/preflight.py`. Команда только читает состояние и проверяет Compose.
2. Завершить локальную проверку актуального кода, собрать Linux/amd64 образы на отдельной машине, проверить отсутствие Enterprise. Перенести проверенные образы и зафиксировать их digest/manifest; сервер не использовать для ресурсоёмкой сборки frontend.
3. После разрешения владельца на запуск: оператор проверяет `.env`, адреса первоначальных сотрудников, свободный порт, резервное копирование и комплект образов. `bash scripts/server/start.sh --approved` — будущая команда запуска, сейчас её не выполнять. Нужны также базовые образы из lock-файла: скрипт запуска использует `--pull never`, отсутствующие образы должны быть подготовлены заранее.
4. Проверить здоровье сервисов, миграции, роли и изоляцию. Затем отдельно авторизовать Telegram интерактивно: код и 2FA вводятся оператором, session хранится только в приватном каталоге. До авторизации gateway не должен отправлять настоящие сообщения.
5. Для внутреннего просмотра через SSH: `ssh -N -L 8088:127.0.0.1:8088 fornex.pravburo`, затем `http://localhost:8088`. Публичный домен/TLS настраиваются отдельно, до внешнего доступа.

Скрипт `prepare-env.py` намеренно отказывается перезаписывать существующий `.env`. Секреты нельзя выводить через `docker compose config` без `--quiet` или включать в архивы исходников. Первоначальные учётные данные находятся только в серверном `.env`; пока bootstrap не выполнен, соответствующих пользователей в БД нет.

## Публичный домен

Основной адрес — `https://mess.prav-buro.ru`. A-запись указывает на `162.248.166.241`, публичный nginx проксирует в `127.0.0.1:8088`, внутренний proxy сохраняет HTTPS-схему для защищённых cookies. Конфигурация отдельного сайта: `/etc/nginx/sites-available/chatwoot-mess.prav-buro.ru`. Сертификат и renewal конфигурация управляются Certbot. Скрипт для воспроизведения: `python3 scripts/server/configure-domain.py mess.prav-buro.ru`; до изменений он проверяет DNS и сохраняет приватную копию `.env`.
