# MAX Personal gateway

Собственный шлюз пользовательского аккаунта на закреплённом PyMax 2.5.0 (MIT). Это не бот и не официальный API MAX. Авторизация QR/2FA доступна только техническому администратору через Rails → Django → gateway. Сессия и SQLite-журнал находятся в приватном secrets/max. Порт не публикуется, телеметрия и SDK-логи выключены.

Поддержаны поиск разрешённого номера, отправка обычного текста, ответ, правка текста/подписи с сохранением вложений, приём личных диалогов, фото, документов, аудио и видео. Группы и каналы не импортируются. MAX_DELIVERY_ENABLED=false сохраняет только авторизацию и закрывает доставку. MAX_TEST_PEER_IDS ограничивает обмен тестовыми пользователями; MAX_TEST_PHONE разрешает найти выбранного испытателем собеседника. Пустой список разрешает личные диалоги после приёмки. MAX_CRM_ENABLED отдельно управляет автоматическими изменениями CRM.

Текст сохраняется до загрузки файлов. SQLite WAL/FULL, ACK только после сохранения в интеграционной БД, отдельные подтверждения обработки и отложенные задания медиа. Подписи событий убирают повторы; смена канала участвует в ключе. Неопределённый результат не отправляется повторно: операция проверяется по CID в истории или уведомлении MAX. Сам по себе доступный WebSocket не считается авторизованной сессией.

Несколько выбранных файлов интерфейс отправляет отдельными сообщениями: MAX не принимает смешанный пакет фото+документ. Файлы до 20 МиБ проходят ограничения размера, защищённую загрузку с публичных HTTPS CDN платформы, проверку типа и ClamAV общего контура. Неподдерживаемое вложение остаётся видимой ошибкой рядом с сохранённым текстом. Голосовые OGG/Opus отправляются как голосовые, прочие аудио/видео могут отправляться документом. Полная старая история до включения канала не импортируется. Догрузка после разрыва ограничена доступной платформе историей; правки ищутся также в последних 30 сообщениях. Удаление, сделанное офлайн и не выданное MAX при reconnect, нельзя гарантированно восстановить. Гарантия 100% доставки внешней платформы не заявляется.

Завершённые события и файлы очищаются через 30 дней; незавершённые не удаляются. Ключи операций/индексы сообщений сохраняются для дедупликации, без исходного текста завершённых операций. Рабочая история остаётся в Chatwoot. Сессия MAX пока не включена в прежний backup; процедуры backup этим выпуском не изменяются.

Unit tests: `cd gateways/max && .venv/bin/python -m unittest test_connection test_messaging`. Установка зависимостей — requirements.lock с проверкой хешей. Рабочая матрица испытаний: [max-poc.md](../../docs/max-poc.md).
