# MAX Personal: пилот подключения

Изолированный пользовательский шлюз на PyMax 2.5.0, MIT. Решение: [ADR 0005](../../docs/decisions/0005-max-personal-pilot.md). Это не официальный API MAX и не бот.

Первый выпуск: QR/2FA, приватная сессия, восстановление соединения и защищённый статус. Контроль доступен только техническому администратору через Rails → Django → gateway. Порт на хост не публикуется. Телеметрия SDK отключена, его логи не выводятся. Пароли передаются в POST body и не сохраняются; QR живёт только в памяти процесса и приватном интерфейсе. Файлы session/control находятся в secrets/max, вне Git.

Нет API отправки сообщений, импорта истории или передачи переписок менеджерам/CRM/AI. SDK login/sync может получить списки чатов в оперативной памяти, но они не выдаются из gateway. Live-функции и пределы ещё предстоит проверить по [матрице PoC](../../docs/max-poc.md).

Подготовка окружения: `python3 scripts/server/prepare-max.py` (из корня). Она генерирует только внутренний service token, включает профиль max-poc и создаёт приватный каталог; вход в MAX не выполняется. Unit tests: `cd gateways/max && .venv/bin/python -m unittest test_connection`. Установка зависимостей выполняется из requirements.lock с проверкой хешей.
